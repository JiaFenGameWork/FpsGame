## 验证寻路优化的步骤

### 1. 展开 PlayerLoop 查看细节

**在 Profiler 中操作**：

1. 点击下方 Hierarchy 中的 **"PlayerLoop"** 行
2. 展开它（点击左侧三角形）
3. 查找寻路相关的条目

**应该看到类似**：
```
▼ PlayerLoop (15.1%)
  ▼ Update.ScriptRunBehaviourUpdate
    ▼ BaseEnemyController.Update
      └─ StateMachine.Update
        └─ PatrolState.Tick / RandomPatrolState.Tick
  ▼ Coroutines
    └─ NePathFinder.FindPathAsy  ← 这里！
```

### 2. 查找寻路协程的耗时

**搜索方法**：

1. 在 Hierarchy 顶部搜索框输入：`FindPathAsy`
2. 或者输入：`Pathfinding`
3. 查看耗时数据

**优化前 vs 优化后**：

| 指标 | 优化前 | 优化后（目标）|
|------|--------|---------------|
| 单帧最大耗时 | 100+ ms | < 5 ms |
| 调用次数 | 1次处理完 | 分多帧处理 |
| Timeline | 有高峰 | 平稳 |

### 3. 触发寻路测试

**操作步骤**：

1. **继续运行游戏**（保持 Profiler 录制）

2. **触发敌人寻路**：
   - 让敌人移动到新的巡逻点
   - 或者让敌人追踪玩家
   
3. **观察 Profiler**：
   - 看 Timeline 是否有突然的高峰
   - 查看 FindPathAsy 的耗时

### 4. 使用 Deep Profile（可选）

**开启方式**：

1. **停止游戏**
2. 点击 Profiler 顶部的 **"Deep Profile"** 按钮
3. **重新运行游戏**
4. 触发寻路
5. 查看详细的调用栈

**注意**：Deep Profile 会显著降低性能，只用于分析！

### 5. 添加自定义标记验证

**在代码中添加**（已经修改的 NePathFinder.cs）：

```csharp
public IEnumerator FindPathAsy(Vector3 startPos, Vector3 targetPos, Action<List<Vector3>> ondone)
{
    UnityEngine.Profiling.Profiler.BeginSample("PathFinding.Total");
    
    // ... 初始化代码 ...
    
    int nodesProcessedThisFrame = 0;
    const int maxNodesPerFrame = 50;
    
    while (openSet.Count > 0)
    {
        UnityEngine.Profiling.Profiler.BeginSample("PathFinding.ProcessNode");
        
        // ... 处理节点 ...
        
        UnityEngine.Profiling.Profiler.EndSample();
        
        nodesProcessedThisFrame++;
        if (nodesProcessedThisFrame >= maxNodesPerFrame)
        {
            nodesProcessedThisFrame = 0;
            yield return null; // ← 关键：分帧
        }
    }
    
    UnityEngine.Profiling.Profiler.EndSample();
}
```

这样在 Profiler 中就能直接看到 "PathFinding.Total" 和 "PathFinding.ProcessNode"。

## 判断标准

### ✅ 优化成功的标志

- [ ] Timeline 平稳，无明显高峰
- [ ] FindPathAsy 单次耗时 < 1ms
- [ ] 多个敌人同时寻路也不卡
- [ ] CPU 主线程时间稳定 < 16.67ms

### ⚠️ 可能还需要优化

- [ ] Timeline 仍有周期性高峰
- [ ] FindPathAsy 耗时 > 5ms
- [ ] CPU 时间经常 > 20ms
- [ ] 敌人移动时明显卡顿

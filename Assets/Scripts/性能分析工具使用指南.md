# Unity 性能分析工具使用指南

## 🎯 目标
学会使用 Unity Profiler 和其他工具快速定位性能瓶颈和卡顿原因。

---

## 📊 一、Unity Profiler（主要工具）

### 1. 打开 Profiler

**路径**：`Window → Analysis → Profiler`

**快捷键**：`Ctrl + 7` (Windows) / `Cmd + 7` (Mac)

### 2. 开始性能分析

#### 方法A：编辑器模式分析
1. 打开 Profiler 窗口
2. 点击 **Record** 按钮（红色圆点）
3. 运行游戏（Play Mode）
4. 重现卡顿场景
5. 暂停游戏或停止录制

#### 方法B：真机/构建版本分析（推荐）
1. `File → Build Settings → Development Build` ✅
2. 勾选 `Autoconnect Profiler` ✅
3. Build and Run
4. Profiler 会自动连接到运行的应用
5. 重现卡顿

> **注意**：编辑器模式会有额外开销，真机数据更准确！

### 3. 查看各项性能指标

Profiler 提供多个模块：

#### 🔴 **CPU Usage（最重要）**
显示每帧各系统的CPU占用时间

**关键列**：
- **Timeline**：时间轴，可以看到哪些帧卡顿（高峰）
- **Hierarchy**：调用层级，双击可以深入查看
- **Total**：总耗时
- **Self**：自身耗时（不包括子调用）
- **Calls**：调用次数

**查找卡顿步骤**：
1. 在 Timeline 中找到卡顿的帧（高峰）
2. 点击该帧
3. 在下方 Hierarchy 查看耗时最多的函数
4. 按 **Total** 或 **Self** 排序

**常见卡顿来源**：
```
▼ PlayerLoop
  ▼ Update
    ▼ ScriptUpdate          ← 脚本Update
      └─ YourScript.Update  ← 你的脚本（如寻路）
  ▼ PreLateUpdate
    └─ Physics.Processing   ← 物理计算
  ▼ Rendering
    ├─ Camera.Render        ← 渲染
    ├─ Shadows              ← 阴影
    └─ Culling              ← 剔除
```

#### 🟢 **GPU Usage**
显示GPU渲染时间

**关键指标**：
- **Rendering**：总渲染时间
- **Shadows**：阴影
- **Opaque**：不透明物体
- **Transparent**：透明物体

#### 🟡 **Memory**
显示内存使用情况

**关键指标**：
- **Total Allocated**：总分配内存
- **GC Allocated**：托管内存（C#对象）
- **GC Reserved**：GC预留内存

**警告信号**：
- GC Allocated 快速增长 → 内存泄漏
- 频繁的 GC.Collect → 垃圾回收导致卡顿

#### 🔵 **Rendering**
显示渲染统计

**关键指标**：
- **SetPass Calls**：材质切换次数（越少越好）
- **Batches**：批次数量（越少越好）
- **Triangles**：三角形数量
- **Vertices**：顶点数量

### 4. 深度分析（Deep Profile）

**开启方式**：点击 Profiler 顶部的 **Deep Profile**

**作用**：
- 记录所有函数调用（包括Unity内部）
- 可以精确定位到具体哪一行代码慢

**注意**：
- ⚠️ 会严重影响性能，只用于定位问题
- ⚠️ 不要在 Deep Profile 下衡量真实性能

### 5. 查看具体代码位置

**步骤**：
1. 在 Hierarchy 中找到耗时的函数
2. 右键 → **Show in Profiler**（或双击）
3. 如果是你的代码，会打开脚本并跳转到对应行

## 🔍 二、Frame Debugger（渲染分析）

### 作用
逐步查看每一帧的渲染过程，找出渲染瓶颈。

### 使用步骤

1. **打开 Frame Debugger**
   - `Window → Analysis → Frame Debugger`

2. **启用**
   - 点击 **Enable** 按钮
   - 运行游戏

3. **逐步查看渲染**
   - 左侧列表显示所有 Draw Call
   - 使用滑块或箭头逐步查看
   - 右侧显示当前渲染结果

4. **查找问题**
   ```
   ✅ 批次数量过多？
   ✅ 重复渲染？
   ✅ 不必要的阴影？
   ✅ 过度使用透明材质？
   ```

## 📈 三、Stats 窗口（实时监控）

### 打开方式
在 Game 窗口点击右上角 **Stats** 按钮

### 关键指标

```
FPS:         60 (帧率，越高越好，通常目标60)
CPU main:    8.2ms (CPU主线程时间，<16.67ms 才能保持60fps)
CPU render:  2.1ms (CPU渲染线程时间)
Batches:     150 (批次数，越少越好，一般<1000)
SetPass:     45  (材质切换，越少越好，一般<100)
Tris:        50k (三角形数量)
Verts:       80k (顶点数量)
```

### 性能目标

**60 FPS 目标**：
- CPU main < 16.67 ms
- 每帧预算约 16.67 毫秒

**30 FPS 目标**：
- CPU main < 33.33 ms

## 🛠️ 四、常见卡顿场景排查

### 场景1：每隔几秒卡一下

**可能原因**：
1. **寻路计算**（你的情况！）
2. **对象池回收/生成**
3. **定时保存**
4. **GC（垃圾回收）**

**排查步骤**：
```csharp
// 在 Profiler 中查找：
1. CPU Usage → Timeline
2. 找到卡顿帧（高峰）
3. 展开 Hierarchy 查看具体函数
4. 常见元凶：
   - FindPathAsy / FindPath
   - Instantiate / Destroy
   - GC.Collect
   - Save / Load
```

### 场景2：进入某个区域开始卡

**可能原因**：
1. **LOD（细节层级）设置不当**
2. **光源过多**
3. **粒子特效过多**
4. **复杂阴影**

**排查步骤**：
```
1. Profiler → Rendering
2. 查看 Draw Calls / Batches
3. Frame Debugger 查看具体渲染内容
4. 检查：
   - 光源数量（特别是实时阴影）
   - 粒子系统数量
   - 透明物体数量
```

### 场景3：角色动作时卡

**可能原因**：
1. **动画系统**
2. **物理碰撞计算**
3. **骨骼动画过于复杂**

**排查步骤**：
```
Profiler → CPU Usage
1. Animator.Update 耗时
2. Physics.Processing 耗时
3. SkinnedMeshRenderer.Update 耗时
```

### 场景4：整体持续卡顿

**可能原因**：
1. **渲染瓶颈**
2. **物理模拟过多**
3. **脚本优化问题**

**排查步骤**：
```
1. 检查 FPS 和帧时间
2. CPU vs GPU 谁是瓶颈？
   - Stats 窗口对比 CPU main 和 GPU time
   - CPU main 高 → CPU瓶颈（优化脚本/物理）
   - GPU time 高 → GPU瓶颈（优化渲染）
```

## 💡 五、使用 Profiler 标记自定义代码

### 添加自定义标记

在你的代码中添加性能标记，方便在 Profiler 中定位：

```csharp
using UnityEngine.Profiling;

public class YourScript : MonoBehaviour
{
    void Update()
    {
        // 方式1：使用 Profiler.BeginSample
        Profiler.BeginSample("My Custom Section");
        
        // 你的耗时代码
        DoSomethingExpensive();
        
        Profiler.EndSample();
        
        // 方式2：使用 CustomSampler（推荐，性能更好）
        // CustomSampler sampler = CustomSampler.Create("My Sampler");
        // sampler.Begin();
        // DoSomethingExpensive();
        // sampler.End();
    }
}
```

### 示例：标记寻路代码

```csharp
public IEnumerator FindPathAsy(Vector3 startPos, Vector3 targetPos, Action<List<Vector3>> ondone)
{
    Profiler.BeginSample("Pathfinding - Total");
    
    // 初始化
    Profiler.BeginSample("Pathfinding - Init");
    Vector3Int startGrid = WorldToGrid(startPos);
    Vector3Int targetGrid = WorldToGrid(targetPos);
    MinHeap<PathNode> openSet = new MinHeap<PathNode>(2048);
    // ...
    Profiler.EndSample();
    
    while (openSet.Count > 0)
    {
        Profiler.BeginSample("Pathfinding - Process Node");
        // 处理节点
        Profiler.EndSample();
        
        yield return null;
    }
    
    Profiler.EndSample();
}
```

在 Profiler 中就能看到：
```
▼ Your Script.FindPathAsy
  ├─ Pathfinding - Total (10.5ms)
  │  ├─ Pathfinding - Init (0.5ms)
  │  └─ Pathfinding - Process Node (0.2ms, 50 calls)
```

## 🎓 六、实战演练：定位你的卡顿问题

### 步骤1：记录卡顿
```
1. 打开 Profiler (Ctrl+7)
2. 点击 Record
3. Play 游戏
4. 等待卡顿发生
5. 停止 Record
```

### 步骤2：查找卡顿帧
```
1. CPU Usage 视图
2. Timeline 中找到高峰（卡顿帧）
3. 点击该帧
```

### 步骤3：分析原因
```
1. 查看 Hierarchy，按 Total 排序
2. 展开最耗时的项
3. 找到具体函数
4. 记录：
   - 函数名
   - 耗时
   - 调用次数
```

### 步骤4：验证修复
```
1. 修改代码
2. 再次 Profile
3. 对比修改前后的耗时
4. 确认改进
```

## 📝 七、性能分析清单

### 每次分析都检查

- [ ] **CPU 主线程时间** < 16.67ms（60fps）
- [ ] **GC Alloc** 每帧 < 100KB
- [ ] **Draw Calls** < 1000
- [ ] **SetPass Calls** < 100
- [ ] **Tris/Verts** 在合理范围
- [ ] **Physics.Processing** 耗时合理
- [ ] **Rendering** 耗时均衡
- [ ] **没有频繁 GC.Collect**

### 优化优先级

1. **高优先级**（严重卡顿）：
   - 单帧 > 30ms 的函数
   - 每帧分配 > 1MB 内存
   - GC.Collect 频繁

2. **中优先级**（影响流畅度）：
   - 单帧 10-30ms 的函数
   - 每帧分配 100KB-1MB 内存
   - Draw Calls > 2000

3. **低优先级**（优化空间）：
   - 单帧 < 10ms 的函数
   - 可批处理的渲染
   - 缓存优化

## 🚀 八、其他有用工具

### 1. Memory Profiler（内存分析）

**安装**：`Window → Package Manager → Memory Profiler`

**用途**：
- 详细查看内存使用
- 找出内存泄漏
- 分析纹理/网格占用

### 2. Console 日志分析

在卡顿时输出日志：

```csharp
void Update()
{
    float frameTime = Time.deltaTime * 1000f; // 转换为毫秒
    if (frameTime > 50f) // 如果帧时间 > 50ms（卡顿）
    {
        Debug.LogWarning($"[性能] 卡顿检测: {frameTime:F2}ms at {Time.frameCount}");
    }
}
```

### 3. Unity Performance Reporting（云端分析）

**开启**：`Services → Analytics → Performance Reporting`

**用途**：
- 收集真实玩家的性能数据
- 查看崩溃报告
- 统计帧率分布

## 📚 总结

### 最常用的工具

1. **Unity Profiler** - CPU/GPU/内存全面分析 ⭐⭐⭐⭐⭐
2. **Stats 窗口** - 实时监控 ⭐⭐⭐⭐
3. **Frame Debugger** - 渲染问题 ⭐⭐⭐
4. **自定义 Profiler 标记** - 精确定位 ⭐⭐⭐⭐

### 快速排查流程

```
卡顿发生
    ↓
打开 Profiler
    ↓
找到卡顿帧（Timeline 高峰）
    ↓
查看 Hierarchy（按 Total 排序）
    ↓
定位耗时函数
    ↓
分析原因：
  - 脚本逻辑？→ 优化算法/分帧
  - 物理计算？→ 减少碰撞体/降低精度
  - 渲染？    → 减少 Draw Call/优化材质
  - GC？      → 减少内存分配
    ↓
修改代码
    ↓
再次 Profile 验证
```
